Reports code that assigns a location that the assignable clause of its method does not list.

A method may only change the fields and array elements that existed before it was called if its assignable clause lists them, such as count, next.value, this.* (all fields of the object), values[*] (all elements of the array) or a model field whose data group holds the field (//@ in size;). It may always change its local variables and the objects that it creates itself, and a constructor the fields of the new object. This inspection reports:

  • assignments, also with ++, -- and +=, to a field or array element that the assignable clause does not list;
  • calls of methods that are not pure and have no assignable clause, which may therefore change anything, and of methods whose assignable clause names a location that this method's clause does not list.

Example:


//@ assignable count;
public void reset() {
    count = 0;
    total = 0;          // the assignable clause does not allow assigning to total
}

With several specification cases, a location that one of their assignable clauses lists is allowed; a case without an assignable clause allows everything. Methods without a specification are not checked, and pure methods are checked by Pure method changes state. OpenJML's type checking does not check this; Verify with OpenJML reports the same lines as violations of the assignable clause, and also checks each specification case on its own, and calls of the Java library, such as list.add(x).

Quick fixes add the location to the assignable clause, or declare a called method pure.
